Inside OpenAI’s In-House Data Agent

How a context-first design turns natural-language questions into trusted answers across 70,000 datasets and 600 petabytes.

Author: Krishnamurthi
Primary Source: openai.com/index/inside-our-in-house-data-agent
Platform Scale: 3,500+ Internal Users • 70,000 Datasets
Central PM Thesis

“Context is the moat, not the model. The exact same LLM gives wildly different answers depending on what it knows about your schema, business semantics, and past corrections.”

The transferable proprietary asset in enterprise data agents is neither the model nor the chat window: it is the layered context pipeline and the continuous golden-question evaluation harness.

The 6-Layer Context Architecture

Why raw schema retrieval fails and how OpenAI enriches table semantics before running SQL.

1

Table Usage Frequency

Mines historical query logs to identify which tables are trusted by data teams, preventing the agent from hallucinating against stale, abandoned staging replicas.

2

Human Documentation

Surfaces human-authored schema descriptions, column definitions, and business glossary metrics with freshness confidence scores.

3

Codex Codebase Crawling

The secret weapon: The agent crawls Git repositories (dbt models, Airflow DAGs, SQL transforms) to understand what business logic built the table.

4

Institutional Memory

Searches Slack threads, Google Docs, and Notion spaces while strictly preserving user permissions (pass-through RBAC so the agent never leaks access).

5

Memory & Corrections

When users correct an assumption, the correction is committed into agent memory. In OpenAI’s reported benchmark, this produced a 17× query speedup on repeat workflows.

6

Runtime Context

Injects requester role, team boundaries, and active fiscal calendars into query prompts to resolve vague date windows automatically.

The 5-Stage Agent Execution Loop

Autonomous plan formulation, self-correction, and human auditability.

01

Ambiguity Triage

If a question lacks parameters (e.g. "What were yesterday's signups?"), the agent clarifies timezones or applies smart team-level defaults instead of guessing.

02

Context Retrieval

Searches schema vector index, queries codebase git history, and fetches relevant Slack discussions regarding metric definitions.

03

Plan & SQL Generation

Generates executable ANSI SQL with defensive joins and row-limit ceilings to prevent database cluster resource starvation.

04

Self-Correction & Verification

Executes query in a read-only sandbox. If a syntax error, zero-row anomaly, or cartesian explosion occurs, the error is fed back to the model for automatic query revision.

05

Visible Assumptions & Data Lineage

Delivers the final output accompanied by explicit assumptions, direct links to underlying datasets, and a 1-click option for data analysts to inspect the exact SQL.

5 Transferable Product Management Lessons

  • ✦
    Evaluation Harness is Product Infrastructure: A static benchmark of 200+ "golden questions" must run on every prompt or tool change to prevent silent performance regressions.
  • ✦
    Fewer, Consolidated Tools Beat Many Granular Tools: Consolidating 15 discrete API tools into 3 higher-level tools cut decision latency and tool-selection hallucinations by over 40%.
  • ✦
    Inherit, Do Not Reinvent, Permissions: Passing user tokens directly into downstream systems guarantees compliance without maintaining duplicate access control tables.
  • ✦
    Trust Requires Visible Assumptions: Displaying assumptions upfront turns a "black-box answer" into an auditable recommendation for stakeholders.
