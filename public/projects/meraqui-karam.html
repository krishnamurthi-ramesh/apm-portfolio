AI Candidate Matching & ERP Integration

Recreating the requirements-to-shipping loop for karam.ai: problem framing, recruiter shadowing, model trade-offs, and deterministic ERP sync contracts.

Author: Krishnamurthi (Data Science & Technical Product Intern)
Target Product: karam.ai Enterprise Recruitment Platform
Measured Impact: +15% Match Precision • 15h Saved/Recruiter/Wk
The Production Problem Statement

“Recruiters at Meraqui lack a reliable, context-aware way to instantly identify top-fit candidates for a JD within the ERP workflow, leading to duplicated manual data entry and slow time-to-shortlist.”

Existing keyword-matching systems yielded high recall but extremely poor precision — forcing recruiters to manually read every single resume profile. Replacing unstructured bot answers with deterministic REST API contracts resolved data drift and saved 15 recruiter hours weekly.

Target Users & Workflow Transformation

From tedious manual search to 1-click ranked approval.

Legacy Journey (Friction Heavy)

Manual Boolean Filter & Export

Receive JD → Search ERP via boolean keywords → Export candidate spreadsheet → Manually read dozens of resumes → Manually re-enter shortlisted status back into ERP.

Proposed & Shipped Journey

Context-Aware Auto-Shortlist

Upload JD to ERP → karam.ai surfaces top 10 ranked candidates with 2-sentence LLM-generated rationale referencing specific resume lines → Recruiter approves/rejects with 1 click.

Model Architecture Trade-offs

Deciding which architecture serves operational constraints within budget.

Approach Latency Cost Accuracy / Context Decision Verdict
Zero-Shot Frontier API (GPT-4) High (2–4s per candidate) High ($$$ per batch) Good reasoning, but struggles with internal skill taxonomies. Discard (Too slow & costly)
Pure Semantic Search (Embeddings) Very Low (<100ms) Negligible High recall, poor precision. Misses years-of-experience logic (5 vs 2 yrs). Discard as Standalone
Fine-Tuned SLM + Hybrid Retrieval ~800ms Batch Low (In-house compute) High precision on specialized tech taxonomy; captures nuanced JD criteria. Selected & Deployed

Risk Mitigation & PM Retrospective

Honest evaluation of production challenges and future instrumentation.

Risk: Hallucinated Skills on Resumes

LLMs hallucinate that a candidate has coded in a technology simply because it appeared contextually (e.g., “Company X used AWS” vs “I architected AWS”). Mitigation: Enforced strict Pydantic schema validation in the ETL pipeline against a verified skill taxonomy database.

Risk: Black-Box Rejections Damaging Trust

Recruiters distrust opaque matching numbers without evidence. Mitigation: Required the inference output to surface a 2-sentence rationale quoting the exact line in the resume justifying the high rank.

PM Retrospective: What I Would Do Differently Today

Instrument candidate rejection reasons from Day 1 to differentiate between model accuracy errors vs. poor initial JD specifications. Move from batch scoring to streaming inference so candidates populate as the recruiter types.
