Honest Framing & Evidence Audit

“Text-to-workflow generation is a solved baseline; the unsolved failure mode is ensuring generated automations match real-world store schemas before mutating customer orders.”

When Shopify Engineering published their research on fine-tuning Qwen-32B for Sidekick workflow generation, they disclosed that in a 1% live rollout, the fine-tuned model suffered a 35% lower workflow activation rate than the prompt baseline. Top failure slices: email configurations (25%), diverse condition logic (16%), and integration schema boundaries.

Why FlowLens? The Problem Space

Grounding the product in verifiable merchant pain points and Shopify platform constraints.

01 • Silent Failures

Late Friction Detection

Non-developers write exact-match condition strings like countryCode == "USA", unaware that Shopify GraphQL normalizes addresses to ISO alpha-2 ("US"). Workflows run silently without executing intended actions.

02 • Pre-Wait Discards

Pre-Wait Data Loss

Shopify Flow automatically refreshes core store records after a Wait delay node, but discards temporary outputs from Get, Sum, or Count actions executed before the Wait, leading to broken downstream variable references.

03 • Infinite Loops

Self-Triggering Cycles

Workflows triggered on Order updated that mutate orders without idempotency tags can cause cascade loops, exhausting rate limits and triggering merchant store API throttling.

Technical Feasibility & The Architecture Pivot

Honest engineering boundary analysis across Shopify’s 4 platform surfaces.

Surface Capabilities Public API Accessibility Product Feasibility Verdict
1. Shopify Admin UI Renders step execution DAG & 14-day execution logs server-side. Zero Public API Live diagnostic monitoring (Path A) is technically blocked.
2. Public GraphQL API Exposes flowTriggerReceive to trigger events. Trigger Mutation Only Zero queries exist for historical step execution traces.
3. Exported .flow Files Shopify allows 1-click export and import of workflow JSON DAG schemas. Fully Accessible Path B Selected: Offline Preflight Static Analyzer.
4. Flow Extensions Supports flow_action & flow_trigger app extensions. No Condition Extension Apps cannot inject native custom condition evaluators.

The 5 Deterministic Linting Rules

Defensive AST inspection rules executed pre-activation.

L-01 [WARNING] Schema-Aware Country Code Check

Validates fields established as ISO alpha-2 (shippingAddress.countryCode) against non-compliant formats (e.g. "USA" vs "US").

Schema Guard
L-02 [HIGH RISK] Pre-Wait Data Action Output Misuse

Warns if a step following a Wait node relies on variables from pre-Wait Get, Sum, or Count actions that Shopify automatically discards.

Fatal Drop Guard
L-03 [INFO] Informational No-Action Branch Note

Documents intentional termination branches when conditions are unmet, allowing merchants to verify whether a silent exit was intended.

L-05 [WARNING] Self-Triggering Cycle Detection
